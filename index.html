Overview

A hands-on lab simulating a small business Windows domain, built to practise common help desk, desktop support, and junior systems administration tasks. A large part of the work was troubleshooting configurations that did not work the first time and understanding why each fix worked.

Environment

  • Windows Server 2022 and Windows 11 virtual machines running in UTM on macOS.
  • Active Directory domain coco.coco with domain controller DC-01.
  • Windows 11 client Desktop01 joined to the domain.
  • Example domain users Toto and Sammy.
  • Action1 for endpoint management.

Implementation

  • Configured Windows Server 2022 as the domain controller, providing Active Directory, DNS, Group Policy, and shared resources.
  • Managed users, computers, and security groups in Active Directory Users and Computers, assigning access through groups rather than individual users.
  • Configured NTFS permissions on shared folders: group-based access, Modify/Read/Write rights, removing broad user permissions, and working with inheritance.
  • Used Group Policy Management to configure user and computer settings centrally.
  • Set up SMB file sharing, network paths, and mapped network drives, and tested access with different domain accounts.
  • Joined the Windows 11 workstation to the domain and worked with administrative shares such as C$.
  • Installed the Action1 Deployer on the server and used Action1 to view managed endpoints, system status, vulnerabilities, updates, and reboot requirements.

Documented outcomes

  • Worked through issues with domain logins, standard vs. administrator permissions, NTFS inheritance, security group permissions, shared-folder access, drive mapping, SMB connectivity, Windows Firewall rules, administrative share access, and Action1 agent deployment and connectivity.
  • Both the domain controller and the Windows 11 client connected to Action1 for endpoint visibility.
  • Full write-up, lab architecture, and screenshots published on GitHub.
